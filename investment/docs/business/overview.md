# 金融商業概念模型

> 本文用**金融語言**描述 Pulse 平台的業務模型，與系統架構（`docs/structure/`）分開。
> 目的：建立一個可重新討論的抽象基準，讓後續重構不會被現有 Django app 切分綁架。

---

## 1. 平台定位

Pulse 是一個**個人台股的全生命週期投資作業台**，不是以下任何單一類別：

| 不是 | 為什麼 |
|------|--------|
| ❌ 純券商前端 | 我們有完整選股 / 復盤 / 知識管理邏輯，Shioaji 只是執行通道 |
| ❌ 純量化回測平台 | 我們保留大量主觀操盤元素（筆記、SOP、情緒日誌、敘事研究） |
| ❌ 純社交 / 投顧 | 單人使用，不以推播訊號為核心 |
| ❌ 純資訊儀表板 | 有下單、持倉、風控閉環，不只是看盤 |

**是**：一個**「主觀 + 量化」混合**的作業平台，為單一使用者覆蓋從**敘事研究 → 選股 → 下單 → 監控 → 復盤 → 知識沉澱**的完整閉環。

## 2. 核心金融實體（Domain Entities）

```
┌──────────────────────────────────────────────────────────────┐
│                         Universe 候選池                        │
│                  (台股全體 / 特定產業 / 特定主題)               │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                      Watchlist 觀察池                         │
│          (使用者選定、待進一步研究或等訊號的子集)               │
└──────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        ┌─────────┐     ┌─────────┐     ┌─────────┐
        │ Signal  │     │Strategy │     │Narrative│
        │  訊號   │     │  策略   │     │  敘事   │
        └─────────┘     └─────────┘     └─────────┘
                (量化 × 質化 × 事件混合)
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                     Candidate 候選單                          │
│              (決定進場的個股 + 理由 + 週期 + 部位)              │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                    Position 持倉 + Order 委託                 │
│                 (實際曝險，是資產負債表上的條目)                │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                   ExitSignal 出場訊號 → Trade 成交             │
│              (實現損益，從資產負債表移到損益表)                 │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│              Journal / Report 交易紀錄 + 績效報表              │
│                  (反饋迴圈，改善 Strategy / Narrative)         │
└──────────────────────────────────────────────────────────────┘
```

### 實體釋義

| 實體 | 金融意義 | 現有實作 |
|------|----------|----------|
| **Universe** | 可投資集合 — 受法規 / 流動性 / 市場限制 | `/api/stocks/`（TWSE + TPEx 全體） |
| **Watchlist** | 已認知、進入深度研究名單 | 目前未獨立實作（散落在 Pipeline step1、Tags 篩選、Explorer 收藏） |
| **Signal** | 產生買賣動作的觸發條件 | Pipeline step3（MA / MACD / KD / 突破）+ 策略回測訊號 |
| **Strategy** | 規則集合：Signal + Sizing + Exit 規則的組合 | `/strategy/*`（JSON 持久化） |
| **Narrative** | 質化投資邏輯：產業循環、政策、事件 | `/analysis/workflow`（賽道漏斗）+ `/news`+ 筆記 |
| **Candidate** | 已決定進場、待下單的個股清單 | `trading_core.Candidate`（Scanner / Pipeline commit 產出） |
| **Order** | 送往券商的委託 | `trading_core.Order` |
| **Position** | 未平倉曝險（有成本、有市值） | `trading_core.Position` |
| **ExitSignal** | 觀察到的平倉觸發（**非執行動作**） | `trading_core.ExitSignal` |
| **Trade** | 已成交紀錄 | `trading_core.Trade` |
| **Journal** | 含情緒 / 決策理由的定性紀錄 | `/analysis/workflow/journal` |
| **Report** | 定量績效總結（Sharpe / Max DD / 勝率 …） | `/bookkeeper/report/` |
| **Knowledge** | 跨交易累積的經驗 / 術語 | `/analysis/notes` + `/guide`（Glossary） |

## 3. 交易生命週期（時間軸 / 執行維度）

一筆完整交易的金融生命週期分五階段，對應盤前 / 開盤 / 盤中 / 出場 / 盤後：

```
┌─────────┐   ┌──────────┐   ┌────────────┐   ┌─────────┐   ┌──────────┐
│ RESEARCH│ → │   ENTRY  │ → │ MONITORING │ → │  EXIT   │ → │ REVIEW   │
│  研究   │   │  進場    │   │    監控    │   │  出場   │   │  復盤    │
└─────────┘   └──────────┘   └────────────┘   └─────────┘   └──────────┘
   盤前           開盤              盤中            即時            盤後
```

| 階段 | 金融問題 | 現有功能 |
|------|----------|----------|
| **Research** | 該不該買？買哪一檔？ | Explorer、Tags、Scanner、Pipeline step1–3、Workflow（政策 / 預算 / 基本面 / 技術） |
| **Entry** | 買多少？什麼價位？怎麼下單？ | Pipeline step4（Sizing）+ Trader（等權、RiskGuard） |
| **Monitoring** | 持倉還健康嗎？該警戒了嗎？ | Watchdog Home.vue（純監控）+ watchdog_loop（背景） |
| **Exit** | 該平倉了嗎？一次 or 分批？ | Exiter（消化 ExitSignal → 全量平倉） |
| **Review** | 這筆賺 / 虧是因為什麼？怎麼改進？ | Bookkeeper（定量報表）+ Journal（定性日誌）+ Workflow/Review（每月復盤） |

**關鍵設計原則**：階段之間**單向傳遞** + **語義不重疊**：
- Research 不接觸實單、Monitoring 只觀察不執行、Exit 只執行不觀察
- 這跟業界量化平台（Zipline / Backtrader / QuantConnect）的切法一致

## 4. 決策層級（控制維度）

每次進場決策都涉及三個獨立層次，容易混淆但必須分離：

```
┌──────────────────────────────────────────────────┐
│  STRATEGY LAYER  策略層                          │
│  「該不該做？」                                  │
│  - 訊號生成（MA 交叉、突破、基本面變化）          │
│  - 策略組合、策略權重                             │
└──────────────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────┐
│  ALLOCATION LAYER  配置層                        │
│  「做多少？怎麼分散？」                           │
│  - Position Sizing（等權、凱利、波動度、風險平價）│
│  - 行業 / 主題集中度                              │
│  - 現金 vs 股票比例                               │
└──────────────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────┐
│  EXECUTION LAYER  執行層                         │
│  「怎麼下？什麼時機？」                           │
│  - 市價 / 限價 / TWAP / VWAP / 分批               │
│  - 滑價、衝擊成本                                 │
│  - Paper vs Live                                 │
└──────────────────────────────────────────────────┘
```

**現況**：Pulse 三層都有觸碰，但深度極不均：

| 層 | 現有深度 | 未涵蓋 |
|----|----------|--------|
| Strategy | ✅ 多種訊號組合，有 Scanner + Pipeline 比對 | 策略間配重、策略衰退偵測 |
| Allocation | ⚠️ 只做「等權重」（`capital / N`） | 凱利公式、波動度 sizing、風險平價、主題 / 產業集中度約束 |
| Execution | ⚠️ 只做市價 | 限價、TWAP / VWAP、分批、滑價建模 |

## 5. 風險三層（風險維度）

對應金融業標準「三道防線」，但我們把它攤平成三種風險類型：

```
┌─────────────────────────────────────────────────────────┐
│ 單筆風險 (Per-Trade Risk)                                │
│  - 固定 % 停損 / 停利                                    │
│  - 單筆最大虧損額                                        │
│  → Watchdog / Exiter                                    │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 投組風險 (Portfolio Risk)                                │
│  - 總曝險上限                                            │
│  - 單檔佔比上限                                          │
│  - 最大同時持倉數                                        │
│  - 行業 / 主題集中度（未實作）                            │
│  - 相關性 / Beta（未實作）                                │
│  → RiskGuard                                            │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 系統 / 市場風險 (Systemic Risk)                          │
│  - 流動性急凍                                            │
│  - 黑天鵝（政策、戰爭、疫情）                             │
│  - 券商故障                                              │
│  → 目前未實作（長期規劃）                                 │
└─────────────────────────────────────────────────────────┘
```

**風險是橫切面，不屬於某一階段** — 所以 RiskGuard 是獨立的橫切模組，在 Entry / Monitoring / Exit 三階段都會被引用。

## 6. 量化 × 主觀 混合模式

Pulse 的**核心差異點**在這裡：純量化系統會丟棄「敘事」，純主觀操盤會丟棄「紀律」，我們兩個都要。

### 量化軸（紀律）

- Scanner / Tags 客觀分類
- Pipeline 訊號比對（可回測）
- RiskGuard 固定閾值
- Bookkeeper 定量績效

### 主觀軸（敘事）

- 政策 / 預算 / 基本面賽道（**外部世界發生了什麼**）
- 筆記 / 心得（**我怎麼看這件事**）
- Kanban 看板（**當前正在追蹤什麼主題**）
- SOP 清單 / Journal（**我的執行紀律 + 情緒**）

### 兩軸的交會點

- **Candidate.meta** 可以同時塞訊號分數 + 敘事標籤 + 策略來源
- **Strategy** 可以綁定一個敘事主題（半導體循環、AI 伺服器、高殖利率避險）
- **Review 階段**要同時看**定量績效**（Sharpe / 勝率）+ **定性歸因**（是敘事對、還是執行對、還是運氣）

## 7. 當前實作中缺少的金融概念

以下是金融上重要、但目前系統尚未清楚承載的概念，留給未來重新設計：

| 概念 | 缺口 | 為什麼重要 |
|------|------|------------|
| **Watchlist** | 散落在 Pipeline step1、Tags、Explorer | 「認知 → 關注 → 進場」三階段應該有明確容器 |
| **Strategy ↔ Position 關聯** | 目前 Position 不知道是哪個 Strategy 產生的 | 無法做「策略歸因」— 不知道 PnL 來自哪個策略 |
| **Narrative ↔ Trade 關聯** | Journal 有情緒欄位，但沒結構化的「進場敘事」tag | 無法回答「我基於 AI 主題進場的一批股票整體表現如何」 |
| **Sizing 多樣化** | 只有等權 | 不同策略 / 不同信心度應該對應不同 sizing |
| **Signal Decay** | 沒有「訊號失效」概念 | Candidate 會一直 pending；訊號有半衰期 |
| **Drawdown Triggers** | 沒有「投組級 DD 觸發防禦」 | 整體帳戶跌 > X% 應該降低部位 / 暫停進場 |
| **Tax-Aware Execution** | 沒考慮短線 / 長線、當沖稅負差異 | 台股當沖 0.15% vs 一般 0.3%，影響出場時機 |
| **Settlement 時序** | T+2 交割未被建模 | 可用資金 ≠ 帳戶餘額 |
| **Multi-Strategy Coexistence** | 同一檔股票只能被一個 Candidate 消化 | 不同策略可能想同時買同一檔；應該可「加碼」不是「互斥」 |
| **Attribution** | Bookkeeper 報總體 PnL，不拆「選股 / 擇時 / sizing」 | 無法回答「我賠錢是因為選錯還是出場錯」 |

## 8. 小結

Pulse 的業務模型可以用**一個三維矩陣**表達：

```
          時間軸（生命週期）
          Research → Entry → Monitor → Exit → Review
           │         │         │        │        │
─────────┼─────────┼─────────┼────────┼────────┼─────
Strategy │  選股    │  訊號   │        │        │ 訊號歸因
─────────┼─────────┼─────────┼────────┼────────┼─────
Alloc.   │  Sizing │ 等權    │ 加碼?  │ 減碼?  │ Sizing 歸因
─────────┼─────────┼─────────┼────────┼────────┼─────
Exec.    │ Paper?  │ 下單    │        │ 平倉   │ 滑價評估
─────────┼─────────┼─────────┼────────┼────────┼─────
Risk     │ Entry檢 │ Entry檢 │ 停損停利│ 觸發   │ DD 檢討
─────────┴─────────┴─────────┴────────┴────────┴─────
            ×
          資產軸（目前只有台股現貨；未來 ETF / 期貨 / 選擇權）
            ×
          軸別：量化（紀律） × 主觀（敘事）
```

**目前系統的實作密度**：
- 時間軸 × Strategy / Execution：**中高**
- 時間軸 × Allocation / Risk：**低**（等權 + 固定 % 停損）
- 資產軸：**單一**（只有台股現貨）
- 敘事軸：**工具層已有**（workflow / notes / news）但**未與決策閉環打通**

後續重新設計時，優先補的應該是：
1. **Watchlist 明確化** — 所有入口統一到一個觀察池
2. **Strategy ↔ Candidate ↔ Position ↔ Trade 全鏈關聯** — 可做歸因
3. **Sizing 獨立抽象** — 從 Trader 裡拆出來，可切換演算法
4. **投組風險指標即時化** — 不是等 Bookkeeper 盤後算，而是 Monitoring 就看到
